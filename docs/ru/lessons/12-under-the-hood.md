HLA64 — это ассемблер с сахаром, и с первого урока вы писали команды процессора рядом с `if`,
`for` и выражениями. В этом уроке — подробнее: как транслятор отличает команду от сахара, блоки
`asm { }` и числовые метки, функции вообще без сахара, стек и устройство вызова.

## Путь от текста до программы

```
program.hla ──► транслятор ──► ассемблер (текст) ──► машинный код ──► Mach-O файл ──► процессор
```

1. **Транслятор** превращает HLA64 в ассемблер AArch64: `node src/cli.ts compile program.hla`.
2. **Ассемблер** превращает каждую команду в 4 байта машинного кода. Например, `add x0, x1, x2` —
   это число `0x8b020020`. На вкладке **Machine code** в браузере можно щёлкнуть по любой команде
   и увидеть все её 32 бита.
3. **Линковщик** собирает код, данные и таблицы для загрузчика в исполняемый файл **Mach-O** —
   формат программ macOS — и подписывает его. Посмотреть его устройство можно на вкладке **Mach-O**.

Встроенными средствами macOS собранную программу можно дизассемблировать: `otool -tv program`.

## Команды процессора: правила

Любая строка, которая не похожа на конструкцию HLA64, считается командой ассемблера и попадает
в результат как есть. Имена переменных, параметров, констант, данных, меток и функций в ней
заменяются на регистры и адреса. Первое слово строки — всегда имя команды: оно никогда
не заменяется, даже если совпадает с именем переменной.

```hla
extern printf(fmt, ...)

fn main() {
    let a = 6, b = 7
    mul x9, a, b                 // a и b заменятся на x19 и x20
    printf("6 * 7 = %ld\n", x9)
    let big: x10 = 0
    movz big, #0xbeef            // загрузить 16 бит
    movk big, #0xdead, lsl #16   // и ещё 16 бит выше, не трогая младшие
    printf("big = %lx\n", big)
}
```

```text
6 * 7 = 42
big = deadbeef
```

Несколько команд подряд удобно записывать блоком `asm { }`. В нём можно ставить метки и прыгать
по ним; **числовые метки** (`1:`) можно повторять, а ссылка `1b` означает «ближайшая метка 1 сзади»,
`1f` — «спереди»:

```hla
extern printf(fmt, ...)

fn sum_to(n) {
    asm {
        mov x9, #0          // сумма
    1:
        cbz n, 2f           // n == 0 -> выход
        add x9, x9, n
        sub n, n, #1
        b 1b                // снова к метке 1
    2:
        mov x0, x9          // результат функции — в x0
    }
}

fn main() {
    printf("1 + ... + 100 = %ld\n", sum_to(100))
}
```

```text
1 + ... + 100 = 5050
```

Функция `sum_to` не делает `return`: результат уже лежит в `x0`, а эпилог его не трогает.

Пример посложнее — максимум без единого перехода: `cmp` выставляет флаги, а `csel` выбирает
один из регистров по условию:

```hla
extern printf(fmt, ...)

fn max_branchless(a, b) {
    asm {
        cmp a, b
        csel x0, a, b, gt    // x0 = (a > b) ? a : b
    }
}

fn main() {
    printf("%ld %ld\n", max_branchless(3, 9), max_branchless(-1, -5))
}
```

```text
9 -1
```

**Осторожно:** регистры `x16`, `x17` и `d29 … d31` транслятор использует для своих промежуточных
вычислений. Внутри одной команды или блока `asm` ими пользоваться можно, но не рассчитывайте, что
значение в них доживёт до следующей строки HLA64.

## «Голые» функции

Обычно транслятор добавляет функции пролог и эпилог. Слово `naked` их отключает: вы получаете
ровно те команды, что написали, и сами отвечаете за всё — в том числе за `ret` в конце.

```hla
extern printf(fmt, ...)

naked fn times_ten(v) {      // v — это x0
    add x9, x0, x0, lsl #2   // x9 = v + v*4 = 5v
    lsl x0, x9, #1           // x0 = 10v
    ret
}

fn main() {
    printf("times_ten(42) = %ld\n", times_ten(42))
}
```

```text
times_ten(42) = 420
```

Это самые быстрые функции, но в них нельзя вызывать другие функции (адрес возврата в `x30` никто
не сохранил) и нельзя пользоваться сохраняемыми регистрами `x19 … x28`, не сохранив их самим.

## Стек: `push` и `pop`

Стек — область памяти, в которую можно временно «отложить» регистры. `push` кладёт регистры на
вершину стека, `pop` снимает их обратно. Так можно сохранить временный регистр на время вызова:

```hla
extern printf(fmt, ...)

fn main() {
    x9 = 123
    x10 = 456
    push x9, x10                 // отложить (printf испортит x9 и x10)
    printf("какой-то вызов\n")
    pop x9, x10                  // вернуть
    printf("x9 = %ld, x10 = %ld\n", x9, x10)
}
```

```text
какой-то вызов
x9 = 123, x10 = 456
```

`pop` перечисляет регистры в том же порядке, что и `push`. На ARM64 указатель стека должен быть
кратен 16 байтам, поэтому даже один регистр занимает в стеке 16 байт — об этом `push` заботится сам.

## Как устроен кадр функции

Посмотрим, что транслятор делает с функцией, у которой есть локальный буфер и сохраняемые регистры:

```hla
extern printf(fmt, ...)

fn demo(n: auto) {
    local buf: u8[16]
    let i = 0
    while i < n {
        buf[i] = 'a' + i
        i++
    }
    buf[n] = 0
    printf("%s\n", &buf)
}

fn main() {
    demo(5)
}
```

```text
abcde
```

Пролог и эпилог `demo`:

```asm
_demo:
    stp x29, x30, [sp, #-16]!   // 1. сохранить fp и адрес возврата, sp -= 16
    mov x29, sp                 // 2. x29 = начало кадра
    sub sp, sp, #32             // 3. место: 16 байт buf + 16 байт для x19, x20
    stp x19, x20, [sp]          // 4. сохранить регистры, которые функция будет менять
    mov x19, x0                 //    n: auto -> x19
    ...
    sub sp, x29, #32            // 5. вернуть sp на место (на случай, если он сдвигался)
    ldp x19, x20, [sp]          // 6. восстановить регистры
    mov sp, x29                 // 7. освободить кадр
    ldp x29, x30, [sp], #16     // 8. восстановить fp и адрес возврата
    ret                         // 9. вернуться по адресу из x30
```

Схема кадра в памяти (адреса растут вверх):

```
        старшие адреса
   ┌──────────────────────┐
   │   кадр вызывающей    │
   │       функции        │
   ├──────────────────────┤ ◄── x29 + 16
   │ x30 (адрес возврата) │
   │ x29 (старый fp)      │
   ├──────────────────────┤ ◄── x29
   │ buf: 16 байт         │     buf лежит по адресу x29 - 16
   ├──────────────────────┤
   │ x20                  │
   │ x19                  │
   └──────────────────────┘ ◄── sp
        младшие адреса
```

## Соглашение о вызовах — шпаргалка

| что | где |
|---|---|
| целые аргументы | `x0 … x7` |
| дробные аргументы | `d0 … d7` |
| аргументы `printf` после шаблона | в стеке, по 8 байт (особенность Apple) |
| результат | `x0` (целый), `d0` (дробный) |
| портятся при вызове | `x0 … x17`, `d0 … d7`, `d16 … d31` |
| не трогать | `x18` (зарезервирован macOS) |
| сохраняются | `x19 … x28`, `d8 … d15`, `x29`, `sp` |
| адрес возврата | `x30` |

Всё, что делает транслятор при вызовах, — это аккуратное соблюдение этой таблицы.
