# HLA64 для WebAssembly (wasm32)

Тот же язык, третья платформа: транслятор выдаёт текст WebAssembly (WAT), встроенный ассемблер
превращает его в двоичный модуль `.wasm`, а браузер — или Node — исполняет его нативно, без
эмулятора. У модуля WebAssembly нет операционной системы, поэтому его система — небольшой
рантайм на JavaScript, который отдаёт модулю библиотеку C (`printf`, `malloc`, `fopen`…) как импорты.
Всё работает и в Node, и на странице `dist/hla64.html` (переключатель **Platform** в самом верху).

```
prog.hla ─► src/lang/wasm ─► .wat (плоские инструкции) ─► src/asm/wasm ─► prog.wasm ─► движок браузера / Node
                                                                                         │
                                                          импорты: src/wasm/runtime.ts (printf, malloc, fopen, …)
```

## Командная строка

```sh
node src/cli.ts run     examples/hello.hla --target wasm32   # запустить здесь, в движке WebAssembly из Node
node src/cli.ts compile examples/hello.hla --target wasm32   # текст WebAssembly
node src/cli.ts build   examples/hello.hla --target wasm32   # hello.wasm + hello.html + hello.mjs
node src/cli.ts build   prog.hla --target wasm32 --zip       # … и prog.zip с этими тремя файлами
node src/cli.ts asm     prog.wat                             # собрать .wat, написанный вручную
node src/cli.ts run     prog.wasm -- one "two words"         # готовый модуль; аргументы после --
```

`build` пишет модуль и два способа его запустить:

| файл | зачем |
|---|---|
| `prog.wasm` | модуль: код, данные, импорты системы |
| `prog.html` | страница с консолью: загружает лежащий рядом `prog.wasm` и запускает его в воркере; поле аргументов, код выхода, файлы, которые записала программа (их можно скачать) |
| `prog.mjs` | та же программа в терминале: `node prog.mjs one two` — настоящий stdout, файлы текущего каталога |

Странице, открытой с диска (`file://`), браузер не даёт читать другие файлы, поэтому она один раз
просит `prog.wasm` (выбрать или перетащить на страницу). Отданная по http (`python3 -m http.server`,
GitHub Pages, любой веб-сервер) она загружает модуль сама. На странице-воркбенче
**Download .zip** даёт те же три файла в папке.

## Регистры и соглашение о вызовах

| | |
|---|---|
| целочисленные регистры | `r0`–`r31`: 64 бита (локальные переменные `i64` функции) |
| регистры с плавающей точкой | `f0`–`f31`: `double` (локальные `f64`) |
| параметры | по позиции: `fn f(a, x: f64)` — `a` в `r0`, `x` в `f1` (не больше 16) |
| результат | `r0`, или `f0` у функции, которая возвращает double |
| портится вызовом | ничего: у каждой функции свои локальные переменные, вызов не может изменить регистры вызывающей |
| `let x = …` без регистра | один из `r16`–`r31`, потом ячейка в кадре |
| глобальные псевдонимы (`alias g: r20` вне функций) | глобальная переменная WebAssembly, общая для всех функций |

Функция возвращает double, когда это сказано (`-> f64`) или когда она возвращает выражение с
плавающей точкой; транслятор выясняет это до того, как транслирует вызовы. Double, использованный
как целое (`let n = hypot(6.0, 8.0)`), преобразуется как `int(...)`, целое, переданное в параметр
`double`, — как `float(...)`.

## Инструкции в коде

WebAssembly — стековая машина: инструкция берёт операнды со стека и кладёт туда результат.
`local.get` и `local.set` переносят значения между стеком и регистрами; переменные, параметры и
данные подставляются по имени, как и на других платформах:

```hla
extern printf(fmt, ...)

// собрать 0xRRGGBB на стеке
fn rgb(red, green, blue) {
    local.get red               // red — это r0
    i64.const 16
    i64.shl
    local.get green
    i64.const 8
    i64.shl
    i64.or
    local.get blue
    i64.or
    local.set r0                // регистр результата: return не нужен
}

fn main() {
    printf("0x%06lx\n", rgb(0x12, 0x34, 0x56))
}
```

- Адреса памяти 32-битные (wasm32): адрес, вычисленный в регистре, сначала сужается —
  `local.get p`, `i32.wrap_i64`, `i64.load8_u`. Имя данных — их адрес:
  `i64.const text`, `i64.load offset=counts`.
- `block`, `loop`, `if`, `else` и `end` — ключевые слова и в HLA64, поэтому структурные инструкции
  пишутся в `asm { }`; переход называет свой блок: `loop $sum` … `br_if $sum`.
- `call puts` вызывает функцию системы или программы; к концу каждого оператора стек должен снова
  быть пустым (лишнее — `drop`), транслятор проверяет это и все типы так же, как движок, и называет строку.
- Комментарии в инструкциях — `//`, как везде в HLA64; в сгенерированном `.wat` они `;;`.

Полный пример — [tests/wasm/cases/mixed.hla](../../tests/wasm/cases/mixed.hla); плавающая точка
рядом с `f64.mul` — [tests/wasm/cases/mandelbrot.hla](../../tests/wasm/cases/mandelbrot.hla).

## Память

```
0 ─ 1024        область NULL, не используется
1024 ─ …        данные: строки, data, rodata, обнулённые данные
… ─ +1 МБ       стек: кадры, растёт вниз от вершины (глобальная $sp)
… ─             куча: malloc рантайма (увеличивает память)
```

Регистры и выражения остаются в локальных переменных; в кадре на стеке живёт только то, чему
нужен адрес: переменные и массивы `local`, ячейки `push`/`pop` и вариативные аргументы вызовов
(локальная `$fp` указывает на кадр). Указатель занимает 8 байт (`ptr`), как на других платформах,
поэтому раскладка структур везде одинаковая. Кадр, который не помещается в стек 1 МБ, останавливает
программу с «stack overflow», слишком глубокую рекурсию без кадров ловит движок.

## Поток управления

В WebAssembly нет переходов, только блоки: `br` выходит из `block` или начинает `loop` заново.
Циклы и условия HLA64 превращаются именно в это:

```wat
block $main.end0               ;; while i < 3 { … }
  loop $main.loop2
    local.get $r16
    i64.const 3
    i64.ge_s
    br_if $main.end0           ;; условие ложно: выйти
    …                          ;; тело
    br $main.loop2             ;; ещё раз
  end
end
```

`break` и `continue` (и с меткой цикла) — это `br` к нужному блоку. `goto` работает, когда он
остаётся в списке операторов своей метки (или выходит из вложенных в него блоков): переход вперёд
становится блоком, который кончается на метке, переход назад — циклом, который на ней начинается,
см. [tests/wasm/cases/goto.hla](../../tests/wasm/cases/goto.hla). У `goto` внутрь другого блока
такой формы нет — это ошибка сборки.

## Система

Модуль импортирует функции C, которые вызывает, из рантайма ([src/wasm/runtime.ts](../../src/wasm/runtime.ts);
список — [src/wasm/libc.ts](../../src/wasm/libc.ts)):

- вывод и файлы: `puts putchar putc fputc fputs printf fprintf dprintf sprintf snprintf fflush fopen fclose fread fwrite fseek ftell feof write read getchar`
- процесс: `exit _exit abort getenv system time clock sleep usleep`
- строки и память: `strlen strcmp strncmp strcpy strncpy strcat strchr memcpy memmove memset bzero memcmp malloc calloc realloc free atoi atol strtol atof abs labs qsort rand srand arc4random arc4random_uniform toupper tolower isdigit isalpha isspace`
- математика: `sqrt sin cos tan atan atan2 exp log log10 pow floor ceil round fabs fmod`

Каждый аргумент — `i64` или `f64`. Функция, объявленная с `...` (`extern printf(fmt, ...)`),
импортируется из модуля `"va"`: вызывающая записывает вариативные аргументы в свой кадр, по 8 байт,
и передаёт их адрес — как в ABI wasm32 у clang. Имя, которого нет в списке (опечатка), — ошибка
сборки с номером строки. `printf("%ld")` печатает 64 бита, как в macOS.

`include "std/file.hla"` работает как на других платформах: в воркбенче программа читает файлы
проекта, а то, что она записала, появляется в панели; в `prog.mjs` — файлы текущего каталога; на
скачанной странице записанные файлы предлагаются для скачивания. `main(argc, argv)` получает
командную строку; `qsort` вызывает функцию программы через таблицу функций.

## Чем отличается от ARM64 и x64

- Нет `syscall(...)`, `rbit()`, `rev()`: нет ни операционной системы, ни таких инструкций.
- В инструкциях нет меток и директив ассемблера: структура — это `block`/`loop`/`if`.
- Только программа: статических и динамических библиотек для C нет (модуль — это целая программа;
  `obj` и `lib` недоступны).
- Ошибки — это ловушки движка: целочисленное деление на ноль, обращение за пределы памяти,
  `unreachable` останавливают программу с сообщением, где названа функция
  (`divide by zero (in d, at 0x94 of the module)`); смещение — это адрес на вкладке **Machine code**.
- Указатели на функции — индексы в таблице модуля; `call_indirect` проверяет сигнатуру.
- `naked` ничего не меняет: пролога, который можно опустить, нет, у функции всегда есть свои локальные переменные и блок.

## Инструменты на HLA64, собранные в WebAssembly

Транслятор и ассемблер, написанные на HLA64 ([selfhost/](../../selfhost/README.ru.md)), пользуются
только библиотекой C, поэтому собираются под wasm32 как есть. На странице WebAssembly пример
**Translator in HLA64** превращает `hello.hla` в тот же `hello.s`, что и нативный `hlc`, а
**Assembler in HLA64** делает из него подписанный Mach-O, байт в байт равный результату
TypeScript-линковщика, — прямо в браузере, и этот файл потом запускается на Mac.
