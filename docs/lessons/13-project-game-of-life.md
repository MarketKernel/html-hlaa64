# Урок 13. Проект: игра «Жизнь»

Соберём всё вместе в одной программе — клеточном автомате «Жизнь», который придумал математик
Джон Конвей. Поле состоит из клеток, каждая жива или мертва. На каждом шаге:

- живая клетка, у которой 2 или 3 живых соседа, выживает, иначе погибает;
- мёртвая клетка, у которой ровно 3 живых соседа, оживает.

Соседей у клетки восемь: по горизонтали, вертикали и диагоналям. Поле «замкнём»: правый край
соседствует с левым, нижний — с верхним.

Нам понадобятся: константы (урок 2), арифметика с остатком (3), условия (4), вложенные циклы (5),
функции (6), массивы (7).

## Шаг 1. Поле и рисование

Поле `W × H` храним в массиве байтов: 1 — живая клетка, 0 — мёртвая. Клетка `(x, y)` лежит
в элементе `y * W + x` — строки идут одна за другой.

```hla
extern putchar

const W = 12
const H = 6

data grid: u8[W * H]

fn set_alive(x, y) {
    grid[y * W + x] = 1
}

fn draw() {
    for y in 0..H {
        for x in 0..W {
            putchar(grid[y * W + x] ? '#' : '.')
        }
        putchar('\n')
    }
}

fn main() {
    // «планер»: фигура, которая ползёт по диагонали
    set_alive(2, 1)
    set_alive(3, 2)
    set_alive(1, 3)
    set_alive(2, 3)
    set_alive(3, 3)
    draw()
}
```

```text
............
..#.........
...#........
.###........
............
............
```

`grid[y * W + x] ? '#' : '.'` — тернарный оператор: если байт не ноль, печатаем решётку, иначе точку.
Внутри `set_alive` и `draw` нет вызовов, которые портили бы параметры, — кроме `putchar` в `draw`,
но переменные циклов `x` и `y` созданы через `for` и живут в сохраняемых регистрах.

## Шаг 2. Соседи

Чтобы поле было замкнутым, координаты берём по модулю: для `x = -1` получим `(−1 + W) % W = W − 1` —
последний столбец.

```hla
fn cell_at(x, y) {
    let cx: x9 = (x + W) % W
    let cy: x10 = (y + H) % H
    return grid[cy * W + cx]
}

fn neighbours(x: auto, y: auto) {
    let count = 0
    for dy in -1..=1 {
        for dx in -1..=1 {
            if dx == 0 && dy == 0 { continue }   // сама клетка — не сосед
            count += cell_at(x + dx, y + dy)
        }
    }
    return count
}
```

- `cell_at` никого не вызывает, поэтому параметры (`x0`, `x1`) и временные `x9`, `x10` в ней безопасны.
- `neighbours` вызывает `cell_at` восемь раз, поэтому `x` и `y` объявлены как `auto` — иначе первый же
  вызов испортил бы их (урок 6).

## Шаг 3. Одно поколение

Новое состояние нельзя записывать прямо в `grid`: соседние клетки ещё должны посчитаться по старому.
Поэтому заводим второй массив `next_grid`, а в конце копируем его обратно.

```hla
fn step() {
    for y in 0..H {
        for x in 0..W {
            let n = neighbours(x, y)
            let me = grid[y * W + x]
            let live = 0
            if me == 1 && (n == 2 || n == 3) { live = 1 }   // выживает
            if me == 0 && n == 3 { live = 1 }               // рождается
            next_grid[y * W + x] = live
        }
    }
    for i in 0..W * H {
        grid[i] = next_grid[i]
    }
}
```

## Шаг 4. Вся программа

Добавим счётчик живых клеток и цикл по поколениям:

```hla
extern printf(fmt, ...)
extern putchar

const W = 12
const H = 6
const GENERATIONS = 4

data grid: u8[W * H]
data next_grid: u8[W * H]

fn set_alive(x, y) {
    grid[y * W + x] = 1
}

fn cell_at(x, y) {
    let cx: x9 = (x + W) % W
    let cy: x10 = (y + H) % H
    return grid[cy * W + cx]
}

fn neighbours(x: auto, y: auto) {
    let count = 0
    for dy in -1..=1 {
        for dx in -1..=1 {
            if dx == 0 && dy == 0 { continue }
            count += cell_at(x + dx, y + dy)
        }
    }
    return count
}

fn step() {
    for y in 0..H {
        for x in 0..W {
            let n = neighbours(x, y)
            let me = grid[y * W + x]
            let live = 0
            if me == 1 && (n == 2 || n == 3) { live = 1 }
            if me == 0 && n == 3 { live = 1 }
            next_grid[y * W + x] = live
        }
    }
    for i in 0..W * H {
        grid[i] = next_grid[i]
    }
}

fn population() {
    let total: x9 = 0
    for i: x10 in 0..W * H {
        total += grid[i]
    }
    return total
}

fn draw(generation: auto) {
    printf("поколение %ld, живых клеток: %ld\n", generation, population())
    for y in 0..H {
        for x in 0..W {
            putchar(grid[y * W + x] ? '#' : '.')
        }
        putchar('\n')
    }
}

fn main() {
    // планер
    set_alive(2, 1)
    set_alive(3, 2)
    set_alive(1, 3)
    set_alive(2, 3)
    set_alive(3, 3)
    // «мигалка»: три клетки в ряд, переворачивается каждый ход
    set_alive(8, 2)
    set_alive(9, 2)
    set_alive(10, 2)

    for g in 0..=GENERATIONS {
        draw(g)
        step()
    }
}
```

поколение 1, живых клеток: 8
............
.........#..
.#.#.....#..
..##.....#..
..#.........
............
поколение 2, живых клеток: 8
............
............
...#....###.

............
поколение 3, живых клеток: 8
............

## Как запустить с большим полем

Поменяйте `W`, `H` и `GENERATIONS` — всё остальное посчитается само: размер массивов задан
константными выражениями `W * H`. Попробуйте поле 40 × 20 и 50 поколений в браузере
(`dist/hla64.html`): эмулятор выполнит несколько миллионов команд за доли секунды.

## Что можно улучшить

1. **Начальная позиция из строки.** Опишите фигуру строкой `rodata pattern = ".#.|..#|###"` и разберите
   её в цикле: `.` — мёртвая, `#` — живая, `|` — следующая строка.
2. **Без лишнего копирования.** Вместо копирования `next_grid` в `grid` меняйте местами *указатели*
   на два буфера (урок 8): передавайте в `step` адреса `from` и `to`.
3. **Быстрее.** `cell_at` вызывается восемь раз на клетку. Перепишите `neighbours` без вызовов:
   посчитайте `x - 1` и `x + 1` по модулю один раз и читайте байты напрямую.
4. **Остановка.** Завершайте программу, когда поле перестаёт меняться (сравните `grid` и `next_grid`).
